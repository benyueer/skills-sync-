# 删除操作确认弹窗设计

## 背景

当前删除操作使用浏览器原生 `confirm`，不同入口的文案和触发位置不一致。用户需要应用内的确认弹窗，并且只确认一次。

本次改动覆盖以下删除入口：

- 中央技能：删除技能目录，并卸载所有 Agent 目录中的关联软链接。
- Agent 技能：从指定 Agent 中移除技能或关联。
- 仓库技能：从本地仓库中删除技能目录。

## 目标

- 点击删除时只打开应用内弹窗，不立即调用删除命令。
- 弹窗明确显示技能名称和本次删除的影响范围。
- 用户只需点击一次“确认删除”即可执行操作。
- 删除过程中阻止关闭和重复提交。
- 删除失败时保留弹窗并展示错误，方便重试或取消。
- 所有删除入口复用同一个确认弹窗组件。

## 非目标

- 不要求用户输入技能名称。
- 不连续弹出两次确认。
- 不改变 Rust 删除命令的文件处理逻辑。
- 不增加撤销、回收站或自动备份能力。

## 交互设计

### 弹窗结构

弹窗标题统一为“确认删除技能”，内容包括：

1. 风险提示图标或红色提示区域。
2. 待删除技能名称，使用醒目的等宽文本展示。
3. 根据删除来源生成的影响说明。
4. 删除失败时显示的错误信息。
5. “取消”和红色“确认删除”按钮。

不同来源的影响说明：

- `central`：将彻底删除中央技能，并移除所有 Agent 目录中的关联软链接。
- `agent`：将从当前 Agent 中移除该技能，不删除中央技能源文件。
- `repo`：将从本地仓库中删除该技能目录，后续 Git 状态会显示对应删除。

### 打开与关闭

- 点击技能卡片上的删除操作后打开弹窗。
- 打开弹窗不会执行任何后端命令。
- 非提交状态下，可通过“取消”、点击遮罩或按 `Esc` 关闭。
- 删除进行中不可关闭弹窗。
- 关闭弹窗时清空待删除对象和上一次错误。

### 提交状态

- 点击“确认删除”后进入提交状态。
- 提交期间按钮显示“删除中…”。
- 两个按钮均禁用，防止重复调用或中途关闭。
- 删除成功后关闭弹窗，并执行该入口已有的列表和状态刷新。
- 删除失败后退出提交状态，保留弹窗并显示错误信息。

## 组件设计

新增可复用的 `DeleteConfirmationDialog` 组件。

建议属性：

```typescript
type DeleteTargetType = 'central' | 'agent' | 'repo'

interface DeleteTarget {
  type: DeleteTargetType
  skillName: string
  contextLabel?: string
}

interface DeleteConfirmationDialogProps {
  target: DeleteTarget | null
  deleting: boolean
  error: string | null
  onCancel: () => void
  onConfirm: () => Promise<void> | void
}
```

组件负责展示、键盘和遮罩交互，不直接调用 Tauri。页面或拥有删除命令的容器负责：

- 保存 `DeleteTarget`。
- 调用对应的 Tauri 删除命令。
- 管理提交状态和错误。
- 删除成功后刷新数据。

`SkillCard` 不再调用浏览器原生 `confirm`。它只向上层发送删除意图，由上层打开统一弹窗。

## 数据流

1. 用户点击删除。
2. 页面设置 `DeleteTarget`，弹窗打开。
3. 用户取消：清空目标，不调用后端。
4. 用户确认：页面根据 `target.type` 调用对应删除命令。
5. 成功：刷新列表和状态，清空目标并关闭弹窗。
6. 失败：保留目标，展示错误，允许重试或取消。

删除命令映射保持现有接口：

- `central` -> `delete_central_skill`
- `agent` -> 现有 Agent 删除或解除关联命令
- `repo` -> `delete_repo_skill`

仓库页面当前处于重构或移除状态时，公共弹窗仍应支持 `repo` 类型；仓库删除入口恢复或迁移后直接复用，不另写确认逻辑。

## 可访问性

- 使用 `role="dialog"` 和 `aria-modal="true"`。
- 标题通过 `aria-labelledby` 关联。
- 打开后将焦点移入弹窗，默认聚焦“取消”，避免误删。
- `Esc` 仅在非提交状态下关闭。
- 危险按钮使用文字与颜色共同表达风险。

## 错误处理

- 后端错误转换为字符串并显示在弹窗内。
- 错误出现后不自动关闭弹窗。
- 再次确认前清除旧错误。
- 取消后清除错误，下一次打开不显示历史失败信息。

## 测试与验证

项目当前未配置前端测试框架，因此实现阶段采用以下验证层级：

1. 将弹窗状态和影响文案提取为可独立验证的纯逻辑，若引入测试框架则优先覆盖这些行为。
2. 运行 `pnpm build`，验证 TypeScript 和生产构建。
3. 运行 Rust 侧现有测试或至少执行 `cargo check`。
4. 在应用中手工验证中央、Agent 和仓库三个入口：
   - 点击删除只打开弹窗。
   - 取消、遮罩和 `Esc` 不触发删除。
   - 确认只调用一次删除命令。
   - 删除中不可重复提交或关闭。
   - 成功后关闭并刷新。
   - 失败后保留弹窗并显示错误。
5. 确认代码中不再存在删除流程使用的浏览器原生 `confirm`。

## 验收标准

- 所有可见删除入口均使用应用内确认弹窗。
- 删除前只需一次显式确认。
- 弹窗准确显示技能名和影响范围。
- 取消不会产生任何文件或链接变更。
- 删除进行中不能重复提交。
- 删除失败可见且可重试。
- 不修改现有 Rust 删除语义。
